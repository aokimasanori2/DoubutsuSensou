# 2台で通信対戦（0.4.0）

両方のAndroid端末に同じ最新版を入れ、インターネットにつないでください。
タイトルの「2だいで つうしんたいせん」を開き、1人が部屋を作ります。
もう1人が8桁の部屋番号を入力します。双方が10個の駒を配置すると、草チームから始まります。
手渡し画面はなく、移動・戦闘・勝敗が相手の画面にも反映されます。

タイトルに戻っても退室しません。「まえの たいせんに もどる」で再開できます。
「おわる」は、対戦開始前は部屋を閉じ、開始後は降参になります。
通信断中は移動を受け付けず、再接続後にサーバーの盤面を読み直します。
部屋は作成から24時間で操作期限が切れます。再戦は新しい部屋を作ります。
アプリを削除・データ消去すると匿名の参加者IDを失うため、元の参加者として戻れません。

## 構成

- Firebaseプロジェクト `doubutsusensou-online` を通信専用に使用。
- Firebase匿名認証で端末ごとの参加者を識別。メールやパスワードの入力は不要。
- Firestore `rooms/{8桁の部屋番号}` に状態を保存し、更新を購読。
- `RoomEngine` はAndroidに依存せず、配置・移動・手番・降参を検証。
- `RoomCodec` のschema=1で盤面を保存。駒IDは固定、位置は20要素の配列。
- `RoomRepository` が認証、保存、監視を担当。`OnlineViewModel` とCompose画面を分離。
- トランザクションとrevisionで同時入室、古い盤面からの二重操作を防止。
- `firebase/firestore.rules` が参加者2名、手番、更新番号、配置の範囲を検証。

## 利用範囲と制約

家族・知人同士で遊ぶテスト版です。相手の駒の種類は画面・読み上げで「？」にしますが、
参加者のアプリには盤面全体が送られます。改造アプリによる駒の解析や、ゲームルールを無視する操作を完全には防ぎません。
対戦結果に賞金やランキングを付ける用途では、秘密の状態と全ルールを信頼できるサーバーへ移す必要があります。
部屋番号を知る認証済みユーザーは空席に入れるため、一緒に遊ぶ相手だけに伝えてください。
入室済みの部屋は参加者だけが読み書きでき、部屋一覧の取得は拒否します。

Sparkプランを使用します。読み書きなどの無料枠を超えると、その日の通信対戦が利用できなくなる場合があります。
24時間はルールによる操作期限であり、データの自動削除ではありません。
期限切れデータと匿名アカウントは管理画面に残ります。大量利用の前に保持期間・削除運用を設計してください。
既存アプリのデータやルールは変更しません。APKの配布先は従来の `kyukabomanager` の対象Androidアプリです。

## 検証と配布

`firebase-tests` のテストはローカルのFirestoreエミュレーターだけを使用します。

```powershell
npm ci --prefix firebase-tests
npx firebase-tools@15 emulators:exec --only firestore --project demo-doubutsu-online 'npm --prefix firebase-tests test'
```

Java 21以上が必要です。CIではルールのテスト、Kotlinテスト、ビルド・lint、Android 15の画面テストが
全て成功した後に、固定のテスト署名でFirebase App Distributionへ配布します。
`app/google-services.json` は通信先の公開設定で、サービスアカウントの秘密鍵ではありません。
本番ルールの変更時はテスト後に通信専用プロジェクトへ反映してください。
